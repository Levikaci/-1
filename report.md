Чтобы получить состояние версии `1.0.1`, специалист может клонировать репозиторий и переключиться на tag:

```bash
git clone <адрес-репозитория>
cd <каталог-проекта>
git switch --detach v1.0.1
```

Если работа выполняется только локально, можно использовать `git switch --detach v1.0.1` из существующего репозитория.

## Контрольные вопросы

### 1. Зачем изменение выполнять в отдельной ветке?
Чтобы изолировать работу над изменением от основной ветки и затем проверить и объединить результат.

### 2. Чем tag отличается от ветки?
Ветка указывает на изменяемую линию разработки и обычно перемещается при новых commit. Tag обозначает конкретный объект/состояние, например выпуск `v1.0.1`.

### 3. Почему hash commit помогает воспроизвести состояние проекта?
Hash однозначно идентифицирует commit в истории Git, поэтому можно найти именно это зафиксированное состояние.

### 4. Что такое конфигурационная базовая линия?
Это зафиксированное согласованное состояние продукта и его конфигурации, с которым можно сверять дальнейшие изменения.

### 5. Почему секреты нельзя включать в `baseline.md`?
Потому что файл может попасть в репозиторий и историю Git, раскрывая пароли, токены и ключи.

### 6. Чем `CHANGELOG.md` отличается от `git log`?
`CHANGELOG.md` описывает изменения версии понятным пользователю или сопровождающему языком, а `git log` показывает историю commit и их метаданные.
